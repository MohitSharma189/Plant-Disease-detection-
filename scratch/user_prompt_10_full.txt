## 4. RESULT PRESENTATION AND PREDICTION-STATE IMPROVEMENT

This is a mandatory implementation requirement of Phase 6A.1.

### 4.1 Current issue

The application currently displays:

- Predicted class: Cherry_(including_sour)___healthy
- Score: 28% uncalibrated score
- Screening result: No regions met the candidate threshold.
- Regions checked: 12

The current presentation may mislead users into interpreting a low-confidence healthy prediction as confirmation that the leaf is healthy.

Improve this behaviour.

### 4.2 Introduce clear prediction states

The application must support the following states:

**A. High-confidence prediction**

When the model score meets the existing verified review threshold:
- Display the predicted class.
- Show the model score with the correct label.
- Clearly identify this as a model prediction.
- Avoid presenting it as a professionally confirmed diagnosis.

**B. Low-confidence prediction**

When the model score falls below the existing verified review threshold:
- Display a prominent but professional "Uncertain Prediction" status.
- Show the top predicted class as a tentative prediction.
- Explain that the model could not produce a sufficiently reliable result.
- Recommend uploading a clearer image or seeking expert confirmation.

Apply this logic equally to healthy and diseased predictions.

A low-confidence healthy prediction must never appear as a confirmed healthy result.

**C. No candidate screening regions**

When no regions meet the screening threshold:
- Display "No Candidate Regions Identified".
- Show the number of regions examined.
- Explain that no regions crossed the screening threshold.
- Clearly state that this does not establish that the leaf is healthy or disease-free.

**D. Candidate screening regions identified**

When candidate regions are detected:
- Display the number of identified regions.
- Show their locations on the uploaded image, if supported by the existing implementation.
- Display relevant screening scores.
- Explain that these are candidate regions requiring further assessment, not confirmed lesions.

### 4.3 Backend and frontend consistency

The backend must determine the prediction state.

The frontend must display the state and warning returned by the backend.

Do not independently implement different confidence thresholds in React and FastAPI.

Locate and verify the existing review threshold.

If the threshold cannot be verified:
- Do not invent a replacement.
- Document the missing configuration.
- Preserve the existing model score.
- Display an appropriate uncertain or unverified state until the threshold is established.

### 4.4 Score presentation

Clearly distinguish:
- Raw model score.
- Calibrated confidence, if verified and available.
- Prediction status.

Uncalibrated scores must be labelled "Uncalibrated Model Score".

Do not call uncalibrated scores calibrated probabilities.

Do not imply that a model score is equivalent to diagnostic certainty.
